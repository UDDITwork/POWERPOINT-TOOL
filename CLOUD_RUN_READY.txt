================================================================================
HOW CLOUD RUN BUILDPACK WORKS WITH /backend SOURCE
================================================================================

Step 1: You configure Cloud Run with source directory: /backend

Step 2: Cloud Build clones your GitHub repo and enters /backend directory

Step 3: Cloud Build Buildpack detects:
  - runtime.txt → "This is a Python app, version 3.11.14"
  - requirements.txt → "Install these dependencies"
  - Procfile → "Use this command to start the app"

Step 4: Cloud Build installs Python 3.11.14 and runs:
  pip install -r requirements.txt

Step 5: Cloud Build creates container with:
  - Python 3.11.14
  - All installed dependencies
  - Your backend/ code
  - Entry command from Procfile

Step 6: Cloud Run starts container and executes:
  uvicorn main:app --host 0.0.0.0 --port $PORT
  (Where $PORT is provided by Cloud Run, typically 8080)

Step 7: Uvicorn loads:
  - Imports main.py from current directory
  - Finds 'app' variable (FastAPI instance)
  - Starts web server on Cloud Run's port

ENTRY POINT VALIDATION
================================================================================

Command in Procfile:
  web: uvicorn main:app --host 0.0.0.0 --port $PORT

This translates to:
  uvicorn           → ASGI web server
  main              → import main.py from /backend
  :app              → get 'app' variable from main.py
  --host 0.0.0.0    → listen on all network interfaces
  --port $PORT      → use Cloud Run's assigned port

The app variable in main.py is:
  app = FastAPI(title="AI Patent Diagram Generator", ...)
